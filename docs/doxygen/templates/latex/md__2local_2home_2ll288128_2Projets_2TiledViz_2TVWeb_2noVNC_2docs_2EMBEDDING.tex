This document describes how to embed and deploy the no\+VNC application, which includes settings and a full user interface. If you are looking for documentation on how to use the core no\+VNC library in your own application, then please see our \doxysectlink{md__2local_2home_2ll288128_2Projets_2TiledViz_2TVWeb_2noVNC_2docs_2LIBRARY}{library documentation}{0}.

\doxysection*{Files}

The no\+VNC application consists of the following files and directories:\+


\begin{DoxyItemize}
\item {\ttfamily vnc.\+html} -\/ The main page for the application and where users should go. It is possible to rename this file.
\item {\ttfamily app/\+} -\/ Support files for the application. Contains code, images, styles and translations.
\item {\ttfamily core/\+} -\/ The core no\+VNC library.
\item {\ttfamily vendor/\+} -\/ Third party support libraries used by the application and the core library.
\end{DoxyItemize}

The most basic deployment consists of simply serving these files from a web server and setting up a Web\+Socket proxy to the VNC server.

\doxysection*{Parameters}

The no\+VNC application can be controlled via a number of settings. All of them are available in the UI for the user to change, but they can also be set via other means:\+


\begin{DoxyItemize}
\item Via the URL, either as a query parameter:\+


\begin{DoxyCode}{0}
\DoxyCodeLine{https://www.example.com/vnc.html?reconnect=0\&shared=1}

\end{DoxyCode}


or as a fragment:\+


\begin{DoxyCode}{0}
\DoxyCodeLine{https://www.example.com/vnc.html\#reconnect=0\&shared=1}

\end{DoxyCode}


The latter might be preferred as it is not sent to the server.
\item Via the files {\ttfamily defaults.\+json} and {\ttfamily mandatory.\+json}
\end{DoxyItemize}

Currently, the following options are available:\+


\begin{DoxyItemize}
\item {\ttfamily autoconnect} -\/ Automatically connect as soon as the page has finished loading.
\item {\ttfamily reconnect} -\/ If no\+VNC should automatically reconnect if the connection is dropped.
\item {\ttfamily reconnect\+\_\+delay} -\/ How long to wait in milliseconds before attempting to reconnect.
\item {\ttfamily host} -\/ The Web\+Socket host to connect to. This setting is deprecated in favor of specifying a URL in {\ttfamily path}.
\item {\ttfamily port} -\/ The Web\+Socket port to connect to. This setting is deprecated in favor of specifying a URL in {\ttfamily path}.
\item {\ttfamily encrypt} -\/ If TLS should be used for the Web\+Socket connection. This setting is deprecated in favor of specifying a URL in {\ttfamily path}.
\item {\ttfamily path} -\/ The Web\+Socket URL to use. It can be either an absolute URL, or a URL relative vnc.\+html. If {\ttfamily host} is specified, then {\ttfamily path} will be interpreted as the path component in the URL instead.
\item {\ttfamily password} -\/ The password sent to the server, if required.
\item {\ttfamily repeater\+ID} -\/ The repeater ID to use if a VNC repeater is detected.
\item {\ttfamily shared} -\/ If other VNC clients should be disconnected when no\+VNC connects.
\item {\ttfamily bell} -\/ If the keyboard bell should be enabled or not.
\item {\ttfamily view\+\_\+only} -\/ If the remote session should be in non-\/interactive mode.
\item {\ttfamily view\+\_\+clip} -\/ If the remote session should be clipped or use scrollbars if it cannot fit in the browser.
\item {\ttfamily resize} -\/ How to resize the remote session if it is not the same size as the browser window. Can be one of {\ttfamily off}, {\ttfamily scale} and {\ttfamily remote}.
\item {\ttfamily quality} -\/ The session JPEG quality level. Can be {\ttfamily 0} to {\ttfamily 9}.
\item {\ttfamily compression} -\/ The session compression level. Can be {\ttfamily 0} to {\ttfamily 9}.
\item {\ttfamily logging} -\/ The console log level. Can be one of {\ttfamily error}, {\ttfamily warn}, {\ttfamily info} or {\ttfamily debug}.
\end{DoxyItemize}

\doxysection*{HTTP serving considerations}

\doxysubsection*{Browser cache issue}

If you serve no\+VNC files using a web server that provides an ETag header, and include any options in the query string, a nasty browser cache issue can bite you on upgrade, resulting in a red error box. The issue is caused by a mismatch between the new vnc.\+html (which is reloaded because the user has used it with new query string after the upgrade) and the old javascript files (that the browser reuses from its cache). To avoid this issue, the browser must be told to always revalidate cached files using conditional requests. The correct semantics are achieved via the (confusingly named) {\ttfamily Cache-\/\+Control:\+ no-\/cache} header that needs to be provided in the web server responses.
