Le lancement de Tiled\+Viz se fait via le script {\ttfamily launch\+\_\+\+Tiled\+Viz} qui démarre le script python {\ttfamily TVSecure.\+py}

Ce script permet, entre autres, de lancer des conteneurs de connexions.

Chaque conteneur a :\+


\begin{DoxyItemize}
\item Un port aléatoire sur lequel le démon {\ttfamily sshd} écoute.
\item Une liste de ports aléatoires pour chaque tuile.
\end{DoxyItemize}

L\textquotesingle{}objectif est d\textquotesingle{}utiliser un pare-\/feu pour bloquer par défaut toutes les connexions entrantes et n\textquotesingle{}ouvrir dynamiquement que les ports nécessaires.

\doxysubsection*{{\ttfamily iptables}, {\ttfamily iptables-\/legacy} et {\ttfamily nftables}}

En fouillant la \href{https://bugzilla.redhat.com/show_bug.cgi?id=1873474\#c4}{\texttt{documentation}} de Red Hat, j\textquotesingle{}ai trouvé cette phrase :\+

\begin{quote}
"{}\+We are not going to include iptables-\/legacy in RHEL8. iptables (nftables or legacy) itself will be deprecated for RHEL9 as well, in preference to nftables."{} \end{quote}


Je me suis donc demandé qu\textquotesingle{}est ce que c\textquotesingle{}est {\ttfamily iptables-\/legacy}, {\ttfamily iptables-\/nft} et {\ttfamily nftables} ?

Ce qui m\textquotesingle{}a amené à 2 supers docs :\+


\begin{DoxyItemize}
\item \href{https://netfilter.org/}{\texttt{netfilter}}
\item \href{https://developers.redhat.com/blog/2020/08/18/iptables-the-two-variants-and-their-relationship-with-nftables}{\texttt{developers.\+redhat.\+com}}
\end{DoxyItemize}

Et voici ce que j\textquotesingle{}ai compris :\+


\begin{DoxyItemize}
\item {\ttfamily netfilter} est un projet qui permet au noyau Linux de filtrer les paquets.
\item {\ttfamily iptables} est un outil de {\ttfamily netfilter} qui permet de définir des règles de filtrage.
\begin{DoxyItemize}
\item Deux variantes d\textquotesingle{}{\ttfamily iptables} existent :\+ {\ttfamily iptables-\/legacy} et {\ttfamily iptables-\/nft}.
\end{DoxyItemize}
\item {\ttfamily nftables} est son successeur qui offre une plus grande flexibilité.
\begin{DoxyItemize}
\item La commande {\ttfamily nft} est utilisée pour manipuler {\ttfamily nftables} avec une syntaxe différente de {\ttfamily iptables}.
\end{DoxyItemize}
\end{DoxyItemize}

\doxysubsection*{Améliorations apportées}

En mettant en place cette solution, nous avons rencontré trois problèmes :\+


\begin{DoxyEnumerate}
\item L\textquotesingle{}utilisation de sudo pour lancer le script Python créait des problèmes de permissions dans toute l\textquotesingle{}arborescence de Tiled\+Viz
\item D\textquotesingle{}autres règles Docker étaient présentes, donc faire un {\ttfamily flush ruleset} à l\textquotesingle{}exécution de {\ttfamily launch\+\_\+\+Tiled\+Viz} les supprimait
\item Le service nftables.\+service géré par systemd lance {\ttfamily /\+etc/\+sysconfig/\+nftables.conf} qui est commenté en entier par défaut, donc que le service soit actif ou non ne changeait rien
\end{DoxyEnumerate}

Il fallait trouver une solution pour manipuler les règles de pare-\/feu sans avoir tous les droits root. C\textquotesingle{}est exactement ce que les capabilities Linux permettent !

\doxysubsubsection*{Capabilities Linux}

Traditionnellement dans UNIX, il existe deux catégories de processus :\+ privilégiés et non privilégiés.


\begin{DoxyItemize}
\item Les processus privilégiés contournent toutes les vérifications de permission du noyau
\item Les processus non privilégiés voient leurs permissions vérifiées en fonction de leur UID et GID effectifs
\end{DoxyItemize}

À partir du noyau 2.\+2, Linux a divisé les privilèges associés à root en plusieurs unités appelées capabilities.

Dans notre cas, {\ttfamily CAP\+\_\+\+NET\+\_\+\+ADMIN} est la capacité qui nous intéresse. Voici sa description dans le man 7 capabilities :\+


\begin{DoxyCode}{0}
\DoxyCodeLine{CAP\_NET\_ADMIN}
\DoxyCodeLine{\ \ \ \ \ \ \ \ \ \ \ \ \ \ Perform\ various\ network-\/related\ operations:}
\DoxyCodeLine{\ \ \ \ \ \ \ \ \ \ \ \ \ \ •\ interface\ configuration;}
\DoxyCodeLine{\ \ \ \ \ \ \ \ \ \ \ \ \ \ •\ administration\ of\ IP\ firewall,\ masquerading,\ and\ accounting;}
\DoxyCodeLine{\ \ \ \ \ \ \ \ \ \ \ \ \ \ •\ modify\ routing\ tables;}
\DoxyCodeLine{\ \ \ \ \ \ \ \ \ \ \ \ \ \ •\ bind\ to\ any\ address\ for\ transparent\ proxying;}
\DoxyCodeLine{\ \ \ \ \ \ \ \ \ \ \ \ \ \ •\ set\ type-\/of-\/service\ (TOS);}
\DoxyCodeLine{\ \ \ \ \ \ \ \ \ \ \ \ \ \ •\ clear\ driver\ statistics;}
\DoxyCodeLine{\ \ \ \ \ \ \ \ \ \ \ \ \ \ •\ set\ promiscuous\ mode;}
\DoxyCodeLine{\ \ \ \ \ \ \ \ \ \ \ \ \ \ •\ enabling\ multicasting;}
\DoxyCodeLine{\ \ \ \ \ \ \ \ \ \ \ \ \ \ •\ use\ setsockopt(2)\ to\ set\ the\ following\ socket\ options:\ SO\_DEBUG,\ SO\_MARK,\ SO\_PRIORITY\ (for\ a\ priority\ outside\ the\ range\ 0\ to\ 6),\ SO\_RCVBUFFORCE,\ and\ SO\_SNDBUFFORCE.}

\end{DoxyCode}


Ces capacités s\textquotesingle{}appliquent sur des fichiers binaires. Dans le cas de TVSecure.\+py qui est lancé via python3, il faut les appliquer sur le fichier binaire de Python.

\doxysubsubsection*{Modifications dans TVSecure.\+py}

Au lieu de créer une chaîne INPUT qui peut porter à confusion, nous créons une chaîne spécifique {\ttfamily TILEDVIZ} (dans le main du script à la fin, et non au début lorsqu’on fait les import et les définitions de variable) :\+


\begin{DoxyCode}{0}
\DoxyCodeLine{nft.cmd(\textcolor{stringliteral}{"{}add\ chain\ ip\ filter\ TILEDVIZ\ \{\ type\ filter\ hook\ input\ priority\ 0\ ;\ policy\ drop\ ;\ \}"{}})}

\end{DoxyCode}


Avant de créer une chaîne, nous la vidons pour éviter les règles redondantes (la distinction entre destroy et delete est importante):\+


\begin{DoxyCode}{0}
\DoxyCodeLine{nft.cmd(\textcolor{stringliteral}{"{}destroy\ chain\ ip\ filter\ TILEDVIZ"{}})}

\end{DoxyCode}


Pour chaque conteneur de connexion qui active la méthode {\ttfamily run}, nous créons une nouvelle chaîne et on insère un {\ttfamily jump} vers cette chaîne dans la chaîne TILEDVIZ :\+


\begin{DoxyCode}{0}
\DoxyCodeLine{nft.cmd(\textcolor{stringliteral}{"{}add\ chain\ ip\ filter\ "{}}\ +\ str(self.name))}
\DoxyCodeLine{nft.cmd(\textcolor{stringliteral}{"{}add\ rule\ ip\ filter\ TILEDVIZ\ jump\ "{}}\ +\ str(self.name))}

\end{DoxyCode}


Cette approche permet de facilement supprimer toutes les règles en même temps que le conteneur en "{}détruisant"{} (destroy) sa chaîne.
